## Anexo A. Student Outcome

El cuadro resume la aplicación de los criterios del Student Outcome 4 al Trabajo Parcial. La evidencia ampliada y su relación con el proyecto se presentan en [Student Outcome](04-student-outcome.md).

| Criterio específico | Aplicación en SafeSpace | Evidencia en el informe |
| :--- | :--- | :--- |
| **4.c.1. Responsabilidad ética y profesional** | El diseño considera la privacidad, la confidencialidad, el anonimato en los reportes y el alcance informativo de la orientación con IA. | Capítulos I, III, IV y V. |
| **4.c.2. Juicios informados sobre impactos** | El equipo analiza el impacto de los canales de bienestar y comunicación en empleados y Recursos Humanos, así como las decisiones técnicas y de servicio asociadas al producto. | Capítulos I, III, V y conclusiones. |

## Anexo D. Glosario técnico

| Término | Definición | Contexto |
| :--- | :--- | :--- |
| API REST | Interfaz que expone operaciones mediante HTTP y recursos. | Comunicación entre aplicaciones y backend. |
| BDD | Desarrollo guiado por comportamiento con escenarios expresados desde la perspectiva del usuario. | Criterios de aceptación y pruebas. |
| CI/CD | Integración continua y prácticas de entrega o despliegue. | Automatización de construcción y publicación. |
| Firestore | Base de datos NoSQL documental administrada por Firebase. | Persistencia de SafeSpace en colecciones y documentos. |
| Colección | Agrupación lógica de documentos en Firestore. | Organización de datos por agregado del backend. |
| Documento | Registro con campos y valores almacenado dentro de una colección. | Representación de entidades y relaciones lógicas de SafeSpace. |
| JWT | JSON Web Token utilizado para transportar información de autenticación. | Seguridad de la API. |
| OpenAPI | Especificación para describir operaciones, esquemas y respuestas de una API. | Documentación de endpoints. |
